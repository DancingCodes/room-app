## Important Product Decisions

- Use simple default Material 3 UI. Do not make complex custom visual design.
- Use two bottom Tabbar pages after login:
  - `首页`: room list.
  - `我的`: current user profile card; card opens edit profile; avatar shows a loading indicator while remote image is loading.
- Separate pages:
  - `创建房间`.
  - `编辑资料`.
  - `房间详情`.
- `RoomScaffold` has been removed; pages use direct layouts, shared `RoomSpacing.ScreenPadding`, and room detail has no top-right leave action.
- Transient errors/prompts use app-level `MessageCenter` + `CenterMessageHost`, centered once; pages should not repeat `ErrorText(state.message)`.
- Room detail has no bottom Tabbar, no profile entry, and leaves only through left-swipe plus confirmation.
- Bottom Tabbar navigation uses `popUpTo(Routes.Home)`, `launchSingleTop`, `saveState` and `restoreState`; repeated Tab taps must not create duplicate back stack entries.
- Active room leave waits for `POST /rooms/:id/leave`; the confirmation dialog stays open in `leaving` state, disables cancel/retry, and only returns home after success.
- Room detail message send action uses a Material 3 filled icon button aligned with the message input.
- Room list top-right entry is only for creating a room; refresh is pull-to-refresh, including empty state.
- Room list items do not display created time; visible time fields elsewhere should use year, month, day, hour, minute and second.

## Auth And User

- Only email-code login is exposed in Android; there are no separate register or forgot-password screens.
- Unregistered emails are expected to be auto-registered by the backend during email-code login.
- Android auth endpoints expected by the client are /api/v1/auth/email-code and /api/v1/auth/email-login.

- Email-code login success should use the returned `user` directly for navigation and local state.
- App startup with existing token calls `/api/v1/users/me`.
- `/api/v1/users/me` is used to validate token and restore current user.
- Avatar picker opens the system gallery directly from the avatar circle; no source menu or text button is shown.
- Edit profile opens a separate page without a visible title, supports changing nickname and avatar, keeps Save at the bottom, and returns to `我的`.
- Avatar selection uses gallery only; edit profile selection is local preview until Save, then `POST /uploads/image` returns `url` and `PATCH /users/me` saves both `nickname` and `avatar_url`.
- Login no longer uses a large top spacer; top spacing is controlled by shared screen padding.

## Room And Chat

- Create room page supports `2人房` and `8人房`, with the Create button pinned to the bottom.
- Default selected room size is `8人房`.
- Full rooms are disabled or clearly shown as full.
- Current user mic control is done from the current user avatar slot in the room member strip; the old Material `Switch` is not used.
- Room detail has `加载更早消息`, a top room title, middle chat area, bottom input row, and a fixed-capacity member avatar strip with empty placeholders and mic badges.
- OkHttp WebSocket uses a 10-second ping interval to keep the room connection alive and detect broken connections faster; the backend sends WebSocket ping every 30 seconds.
- WebSocket abnormal disconnect returns to main home and shows:

```txt
连接已断开，已离开房间
```

## Implemented App Code

- Gradle dependencies are configured for Compose, Navigation Compose, Retrofit, OkHttp, kotlinx.serialization, DataStore and Coil.
- Backend base URL is read from `NetworkConfig.BACKEND_BASE_URL`.
- `RoomApplication` owns a lightweight `AppContainer`.
- `RoomApi` covers the backend HTTP endpoints.
- `TokenStore` persists auth token in DataStore Preferences.
- Basic navigation and screens exist for splash, login, home, me, edit profile, create room and room detail.
- Basic HTTP flows exist for session restore, email-code login, room list, join, create, leave, mic update and text message send.
- Room list supports paginated loading and pull-to-refresh; join loading is tracked per room instead of via list refresh loading.
- Room detail supports loading earlier messages with `before_id`.
- Avatar selection supports gallery through `AvatarPicker`; image upload uses `POST /uploads/image` and profile persistence uses `PATCH /users/me` with both `nickname` and `avatar_url`.
- Room detail connects WebSocket after HTTP detail/messages load and handles member join/left, owner change, message created and mic update events.
- Room detail requests the backend RTC Token and then joins Agora RTC channel `room-{roomId}` after HTTP load, starts muted, renews the Token on SDK expiry callbacks, and leaves the channel on active leave, WebSocket disconnect or ViewModel cleanup.
- WebSocket abnormal disconnect emits its leaving prompt through `MessageCenter` before returning to home.
- HTTP API business `code == 401` is detected by `ApiResponseExt.requireData/requireSuccess`, which triggers `SessionExpiredCenter`; `RoomApp` shows `登录已过期，请重新登录`, clears token, and navigates to login.
- WebSocket handshake or connection failure with HTTP 401 is treated as expired login: show `登录已过期，请重新登录`, clear token, and navigate to login.
- Main Tab switching no longer duplicates navigation back stack entries.
- Room leave confirmation now exposes a visible `离开中` state while the leave API request is in flight.
- Room detail send button is implemented as `FilledIconButton`.
